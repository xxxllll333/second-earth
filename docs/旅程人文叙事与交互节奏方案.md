## 一、背景与目标

### 用户想法（原文提炼）

1. **人文动机开篇**——先回答"为什么要寻找第二地球"。
2. **故事完整弧线**——在现有四个例子的基础上补充信息：这颗星球**何时被发现 → 如何产生希望 → 又如何被证伪（或悬置）**。
3. **数据新鲜度钩子**——标识"最新数据随时更新"，作为回访钩子，增强复用率。

### 设计原则

- 尊重项目核心立场："数据自己说话，用户自己发现"——不编造剧情，三拍全部来自真实科学事件。
- 符合赛道三（科普科教与艺术表达）：戏剧张力服务于科学事实的准确传达。
- 证伪 ≠ 失败叙事。希望→证伪是"科学如何自我修正"的正面教材（呼应卡尔·萨根"非凡的主张需要非凡的证据"）。

## 二、现状梳理

### 现有结构（JourneyPage.tsx）

```
HERO（SECOND EARTH 标题 + 一句话副标题）
  ↓
过渡段（introLines 逐行浮现：数据里"读"出来的世界）
  ↓
行星特写 ×4（3D 球 + tag/headline/一段 narrative + 档案参数行）
  K2-18b / TRAPPIST-1e / WASP-96b / WD 1856b
```

### 缺口

| 缺口 | 现状 | 需要 |
|---|---|---|
| "为什么寻找" | HERO 只有一句"这是一段寻找另一个地球的旅程" | 独立的人文动机章节 |
| 三拍弧线 | narrative 混写发现+希望，无证伪/悬置收尾 | 每星三拍：发现→希望→证伪/悬置 |
| 证伪案例 | TRAPPIST-1d 在星表/星系页有，旅程页缺席 | 旅程页至少一个"完整证伪"故事 |
| 数据钩子 | 仅"我的星表"顶部横幅 | 旅程页行星卡上的实时状态徽章 |

### 数据字段缺口（planets.ts）

现有：`discoveryYear / discoveryMethod / isRejected / hasSpectrum`。
缺：证伪原因、数据更新时间、叙事状态三态。拟增字段（后端 JSON 协议同步扩展）：

```ts
status: 'stable' | 'disputed' | 'rejected'   // 稳健 / 争议中 / 已否决
statusNote: string     // 如 "2025 JWST 证实无大气层" / "DMS 信号待复测"
lastUpdated: string    // "2026.08"，徽章显示用
beats?: [string, string, string]  // 三拍短句（可选，缺省时前端兜底）
```

## 三、叙事素材库（三拍草稿，供细化）

### 序章素材："为什么寻找第二地球"

- 蓝色大理石 → 暗淡蓝点（Pale Blue Dot）：我们的全部文明，都在一粒悬浮的微尘上。
- 太阳终局：约 50 亿年后红巨星吞噬地球 → 白矮星残骸。"行星可以比恒星活得更久，但宜居的窗口稍纵即逝。"
- "我们只有这一扇窗。"
- 此刻进行时：5000+ 已确认行星、中国"地球 2.0"计划（2026 推进中）、MAST 每周都有新光谱上传。

### 故事三拍（希望 → 证伪/悬置）

| 行星 | 拍一·发现 | 拍二·希望 | 拍三·证伪 / 悬置 |
|---|---|---|---|
| K2-18b | 2015 开普勒 K2 凌星发现，氢海世界候选 | 2019 哈勃光谱发现水蒸气——宜居带行星大气含水第一例；2023 韦伯再获 CH₄/CO₂ 与 DMS 痕迹（地球生命专属分子） | 悬置：多团队复测 DMS 结果不一，"生命指纹"仍在辩论 |
| TRAPPIST-1e | 2016–17 发现七行星系统 | 大小/质量/密度与地球惊人相似，ESI 0.85 | 悬置：JWST 正在逐一测大气（进行时） |
| WASP-96b | 2013 凌星发现 | 2022.7.12 韦伯发布**首张系外行星光谱**，水分子指纹清晰——"读谱辨大气"的技术标尺 | 无反转（方法论里程碑，希望的载体是技术本身） |
| WD 1856b | 2020 TESS 发现 | 木星大小的行星竟环绕白矮星——行星可在恒星死亡中幸存 | 悬置：形成机制至今无完美解释，"考古现场" |
| TRAPPIST-1d（拟新增） | 2016 发现，ESI 0.90 曾是最像地球的候选 | "最像地球"的头条与期待 | **证伪**：2025 JWST 证实无大气层、裸岩高温 |
| Proxima b（备选） | 2016 发现，最近的邻居（4.2 光年） | 星际航行梦想的最近驿站 | 存疑：红矮星耀斑风暴可能剥蚀大气 |

## 四、交互节奏方案（四选一 / 可组合）

### 方案 A · 缓流式 —— 滚动长卷轴（现状升级）

- **节奏**：线性、舒缓，单速。用户只控制滚动速度，信息全部在场。
- **结构**：HERO →「为什么」章节（滚动浮现文案）→ 四星特写（每段 narrative 改写为三拍时间轴，竖排三个时间节点）→ 结尾"数据活页"钩子区（全站更新时间 + 收藏入口）。
- **用户动作**：滚动、阅读。
- **成本**：低（改文案 + 局部组件，不碰页面骨架）。
- **适配**：钩子=每星档案行加"更新至 2026.08"小字；结尾数据活页区。
- **缺点**：节奏单一，希望→证伪的反转藏在长文里，戏剧性弱。

### 方案 B · 鼓点式 —— 三拍逐屏揭晓（戏剧张力最强）【已选定】

- **节奏**：三拍式，每拍一屏停顿；用户点击"继续"（或滚动触发）才进入下一拍，反转拍有视觉变奏（如证伪拍行星画面褪色/加红边）。
- **结构**：HERO →「为什么」序章 → 每星：拍一"发现"（年份大字 + 方法）→ 拍二"希望"（数据亮点放大）→ 拍三"证伪/悬置"（反转，行星视觉状态同步变化）。
- **用户动作**：点击/滚动逐拍推进，主动节奏感。
- **成本**：中（每星拆分三屏，滚动监听 + 状态联动已有 framer-motion 基础）。
- **适配**：钩子=拍三收尾处直接出现状态徽章（"已否决 · 2025"），自然引导去"我的星表"。
- **缺点**：四星×三拍 ≈ 12 屏，页面拉长，需精简每拍文案。

#### B+ 细化：交互时间轴（用户选定形态）

在 B 的三拍节奏基础上，竖排时间轴改为**可交互节点**——点击关键时间点弹出对应内容：

```
每行星章节布局
┌────────────────────────────┬────────────────────────────┐
│  3D 星球（随拍同步变化）       │  交互时间轴（竖排三节点）      │
│  [发现拍] 完整色彩           │   ● 2015 · 发现             │
│  [希望拍] 色彩饱满 + 光晕     │   ● 2019 · 希望             │
│  [证伪拍] 褪色 + 红边         │   ● 2025 · 证伪             │
└────────────────────────────┴────────────────────────────┘
```

- **自动模式**：进入章节，时间轴从"发现"开始自动逐拍点亮（间隔约 2.5s），文案区同步显示该拍内容，3D 星球状态联动；播完停留在当前拍。
- **手动模式**：用户点击任意节点 → 中断自动播放，弹出详情卡片（该拍完整文案 3–5 行 + 关键数据点）；证伪拍弹出时附带状态徽章；再次点击或 × 收起。
- **节点视觉**：年份大字 + 关键词；节点色 = 拍状态（发现=白蓝 / 希望=绿 / 证伪=红）；悬停放大 + 预览关键词；已播放节点变实心，未播放节点为空心圆。
- **3D 星球联动**：希望拍增强光晕与色彩，证伪拍降低饱和度 + 红色边缘光（复用程序化星球 `dimmed` 通道即可实现）。
- **移动端**：自动播放为主，点击节点弹出卡片。

### 方案 C · 序曲式 —— 宏大开场 + 故事余韵（人文开场）

- **节奏**：前重后轻。开场是高潮：滚动驱动的尺度动画（地球 → 太阳 → 太阳系 → 50 亿年后太阳终局），落到"为什么寻找第二地球"；四个故事退为精炼卡片，快速扫过。
- **结构**：HERO → 尺度序章（滚动驱动 SVG/3D 缩放，约 3–4 屏）→ 四星故事卡（每卡一行 headline + 三拍微型时间线）→ 数据活页钩子。
- **用户动作**：滚动（序章自动播放节奏），故事区自选停留。
- **成本**：高（序章动画是独立工作量，可先用 SVG 缩放过渡实现）。
- **适配**：钩子=每卡状态徽章 + 结尾"我的星表"引导。
- **缺点**：四星故事被压缩，三拍细节不够展开。

### 方案 D · 胶囊式 —— 速览胶囊 + 按需展开（复用率导向）

- **节奏**：双速。默认速览：每星一条"时间胶囊"——三拍微型时间线（三个年份圆点 + 关键词）横排一行，全页可快速扫完；点击胶囊展开该星的深度叙事区（原位展开/全屏浮层）。
- **结构**：HERO →「为什么」精简段 → 四星胶囊列表 →（展开区按需出现）→ 数据活页钩子。
- **用户动作**：速览扫描 or 点选沉浸，节奏自控。
- **成本**：中（胶囊组件 + 展开态，信息架构略复杂）。
- **适配**：钩子极强——胶囊本身就是回访入口，"更新"徽章高亮未读变化；与"我的星表"回访横幅天然同构。
- **缺点**：首屏信息密度低，第一次来的用户可能只扫胶囊不进深度。
