## 1. 一句话定位与项目速览

## 2. 初心与缘起（一开始的想法）

### 2.1 创作者背景
创作者是**工业设计专业**学生，核心诉求是"获得安全感与实现专业成就"。这决定了作品的独特气质：**不是纯天文科研工具，而是用工业设计的"信息可视化 + 交互叙事 + 克制美学"能力，把硬核天文数据翻译成公众可感知、可理解、可共情的体验。**

### 2.2 人文动机：为什么要找"第二地球"
作品的精神内核来自一条贯穿人类文明史追问的脉络：
- **暗淡蓝点（Pale Blue Dot）**：我们的全部文明，都悬浮在一粒微尘之上——地球是我们目前唯一的家。
- **太阳的终局**：约 50 亿年后太阳膨胀为红巨星吞噬地球，最终坍缩为白矮星残骸。"行星可以比恒星活得更久，但宜居的窗口稍纵即逝。"
- **跨文化的追问**：从伊壁鸠鲁的"无数世界"、布鲁诺的宇宙无限论，到中国《尸子》《天问》对天穹的叩问——"人类是否孤独"是贯穿东西方的永恒命题。
- **此刻进行时**：5000+ 已确认系外行星、中国"地球 2.0"计划推进中、韦伯（JWST）每周都有新光谱上传。寻找第二地球，是**正在发生的科学前沿**，不是科幻。

### 2.3 要解决的三大痛点（传统科普的问题）
1. **结论灌输**——公众只获得简化结论（"这颗行星宜居/不宜居"），看不到原始数据与判断过程。
2. **尺度抽象**——光年、地球半径、平衡温度等量级无法直观感知。
3. **争议遮蔽**——科学本在不断自我修正，但传播中争议常被当作定论（如 K2-18b 的"生命指纹"DMS 信号其实仍在辩论）。

### 2.4 核心设计哲学（贯穿全站的立场）
> **"数据自己说话，用户自己发现。"**

- **不做 AI 弹窗替用户下结论**：系统刻意不用"智能解读"框告诉用户答案，而是靠肉眼可见的曲线差异、光斑颜色、判据清单，让用户**自己完成理解**。
- **应用不替用户思考，而替系统操心**：把力气花在"数据时效性"（后台比对 NASA/MAST 新数据、触发回访提醒）而非"替用户解读"。
- **证伪 ≠ 失败叙事**：希望→证伪是"科学如何自我修正"的正面教材，呼应卡尔·萨根"非凡的主张需要非凡的证据"。
- **不美化数据**：保留原始噪声、误差棒、多团队对比结果。

### 4.1 评分三维体系
| 维度 | 权重 | 细分评分点 |
|---|---|---|
| 科学价值 | 40% | 科学事实准确性(15) + 内容转化清晰度(15) + 主题完整性一致性(10) |
| 技术深度 | 30% | 模型/智能体/技能设计完整性(10) + 多模态数据处理与交互(10) + 结果校验/反馈迭代/稳定性(10) |
| 应用潜力 | 30% | 真实场景使用价值(10) + 演示/交互入口/交付完整度(10) + 代码/结果/流程可复现性(10) |

### 4.2 赛道三加分项与本作品的对齐
- **可复用生成的 AI 应用**：统一的数据拉取/对比/提示逻辑，支持不同行星、用户、时间点的个性化更新视图自动生成。
- **技能包任务闭环**：将数据管道封装为 MCP 技能（exoplanet-spectra-fetcher）——输入行星名→加载 MAST/JWST 预解析数据（含文献 DOI）→标准化 JSON→渲染预览图，最小闭环已通过真实 MCP 协议（stdio）验证可复现运行，产出嵌入光谱档案页；在线 MAST 实时分支（astroquery 下载 FITS）为下一步扩展。
- **多轮使用持续改进**：把"数据过时"视为需修正的不足，后台定时比对 NASA/MAST 最新发布，主动提示用户回访，形成"探索→离开→更新→回访→再探索"闭环。
- **老旧工具接口标准化**：RESTful 封装 MAST Portal；FITS 预解析 + JSON 缓存（目标加速约 250 倍）；Docker 化 + 版本锁定 + 哈希验证保证可复现。

> ⚠️ 诚实边界：MCP 技能包**最小闭环已落地**——`backend/mcp_skill/` 以标准 MCP 协议（stdio）暴露 `fetch_exoplanet_spectra` 工具，走本地预解析缓存分支（MAST/JWST 真实数据离线镜像，含文献 DOI），可运行产出标准化 JSON + 预览图（`backend/scripts/test_mcp_skill.py` 验证通过）；**在线 MAST 分支**（astroquery 下载 FITS）与**自动回访**（`backend/pipeline/` + APScheduler）仍为规划/占位。前端展示的数据为对齐后端协议的硬编码 JSON。

### 5.2 SpaceEngine 美学复刻方案（核心技术参考）
SpaceEngine 是 C++ 桌面软件（全 GPU 着色器管线 + 程序化生成），浏览器无法 100% 复刻，但"神似"完全可行。其美感来源四层拆解 + Web 端 three.js 对应实现：

| SpaceEngine 手段 | three.js 实现 | 难度 | 见效 |
|---|---|---|---|
| 后处理全套（Bloom/ACES/暗角/颗粒） | @react-three/postprocessing | ★☆ | 立刻 |
| 大气散射（边缘蓝晕、晨昏线泛红） | 瑞利/米氏散射 shader（单次散射近似） | ★★★ | 大 |
| 程序化星球表面（无限精度错觉） | ShaderMaterial + fbm 分形噪声实时生成 | ★★ | 大（特写时） |
| 星云背景 | 多层透明 sprite + 噪声贴图 | ★★ | 中 |
| 体积云 | ray marching | ★★★★ | 大但性能紧 |
| LOD 细节层次 | THREE.LOD | ★★ | 特写时必要 |

**落地推进顺序（按性价比）**：后处理升级（零模型改动，整页从"干净 3D 展示"变"有电影感的宇宙"）→ 大气散射 → 程序化星球表面 → 星云背景 + 体积光。学习资源：Shadertoy（Inigo Quilez 的 planet 系列）、three.js 官方 webgl_shaders examples。

## 6. 产品结构：五视图四层穿透叙事（核心架构）

**叙事主线**：星表（宏观普查）→ 星系（单系统 3D）→ 光谱（微观大气）→ 演化（时间维度），构成从宏观到微观、从空间到时间的**层层深入**。外加"旅程"（人文叙事入口）与"我的星表"（收藏回访闭环）。

### 6.1 旅程页（JourneyPage）— 人文叙事入口
- **定位**：先回答"为什么要寻找第二地球"，再用真实科学事件讲述行星的命运弧线。
- **序章**："为什么寻找第二地球"——暗淡蓝点意象，四行文案 blur 逐行浮现 + 数字行。
- **三拍交互时间轴**：每颗行星按 **发现 → 希望 → 证伪/悬置** 三拍叙事。自动逐拍点亮（2.6s/拍），点击任意节点**永久接管**自动播放并弹出详情卡。
- **3D 星球状态联动**：希望拍提亮（曝光 1.42）、证伪拍暗沉 + 灰化 + 红边（曝光 0.72）。
- **五星故事弧线**（刻意重排制造情绪对比）：K2-18b（希望/DMS 争议）→ TRAPPIST-1d（韦伯宣判证伪）→ TRAPPIST-1e（新希望）→ WASP-96b（方法论里程碑：韦伯首张系外行星光谱）→ WD 1856b（终局：行星在恒星死亡中幸存）。
- **状态徽章**：每星收尾落一枚三态徽章（绿=稳健/黄=争议中/红=已否决 + "更新至 YYYY.MM"），与"我的星表"回访横幅同源数据。

### 6.2 星表页（CatalogPage）— 宏观普查
- **定位**：全量系外行星的宏观星图，支持筛选/搜索/穿透。
- **分层渲染架构**（性能核心）：
  - 数据层：拉取 NASA 全量 5000+ 系外行星数据，保证筛选/搜索完整性。
  - 渲染层双层：Canvas 批量撒点生成星空背景（不可点击）+ 精确交互层仅渲染约 30 颗重点行星和筛选命中目标（可点击穿透）。
- **交互**：侧栏筛选（搜索、宜居 checkbox、分类下拉）、星图点击行星弹详情卡（PlanetDetailModal，含分类科普文案 getNarrative()、收藏按钮、跳转链接）。
- **探索模式六站导览飞行**（24 秒慢速巡航 + 里程碑字幕）：地球近景 → 太阳系全景 → **星际邻居** → 本地泡（28 颗系外行星，真实银道坐标 + 对数压缩半径）→ 拉升穿越猎户旋臂 → 银河俯瞰全景。
- **星际邻居层（StellarNeighborhood）**：太阳 12 光年内 15 颗真实命名恒星（比邻星、天狼星、南河三…，RECONS 距离 + J2000 真实方向，与本地泡同一套银道变换），色温着色（红矮星偏红、天狼星蓝白）+ 裸眼星衍射芒 + 轻微闪烁 + 10 光年范围圈；填平“太阳系→系外行星”的尺度跳跃，与本地泡层比邻星 b 形成跨层呼应。

### 6.3 星系页（GalaxyPage）— 单系统 3D 工作台（567 行，最复杂）
- **定位**：进入单个恒星系统，3D 轨道 + 数据面板 + 宜居判决。
- **3D 系统视图（SystemView3D）**：恒星（按光谱型着色：M 红/G 黄/白矮星蓝）+ 椭圆轨道（宜居带内绿色、带外蓝灰）+ 行星位置，支持拖拽旋转/滚轮缩放/点击行星联动。
- **shader 弥散宜居带（HabitableZoneGlow）**：摒弃扁平绿色环带，用三层 sin 噪声调制密度形成团块状明暗起伏、星云式冷暖渐变（内缘青白→中部青绿→外缘蓝紫）、26 颗漂浮微光粒子、纯 additive 叠加无硬边界，模拟能量场。
- **气场光斑判决（AuraVerdict）**：5 枚多层径向渐变光晕光斑表达宜居判据，用**颜色和动画节奏**代替文字清单——通过=青绿缓慢呼吸、边缘=琥珀快速脉动、不满足=暗红黯淡静滞；hover 浮出完整科学判据（如"✓ 272 K 支持液态水 223–323 K"）。
- **地球参照系 3D 对比（EarthReference3D）**：正交投影双球同基线——地球固定为白色基准球（尺子），选中行星球半径 = 真实半径倍数，球顶等宽倍数标签 + 基线每 1 R⊕ 一刻度；切星时行星球弹簧过渡、地球不动；真实比例默认 + 对数档切换。
- **指标条（MetricBar）**：6 条水平双锚点轨（渐变填充 + 行星实点 + 地球白色刻度），切星时实点滑动、数值上浮换入；右栏唯一数值对比视图（原弧线仪表与雷达图信息重复且标签拥挤，已减法合并至此）。

### 6.4 光谱页（SpectrumPage）— 微观大气与争议可视化（亮点核心）
- **定位**：JWST 透射光谱交互，让公众"亲眼看见"科学争议。
- **争议可视化**：同一行星（如 K2-18b）不同团队/仪器的光谱**并列陈列**；拖动"大气强度"滑块，观测曲线与"无大气模型"基线**实时分叉**；可打开误差棒查看 ±1σ。
- **D3 渲染**：光谱曲线、误差带、分子吸收标注（H₂O、CH₄、CO₂、DMS）。
- **关键**：系统不设 AI 弹窗替用户下结论，靠肉眼可见的曲线差异让用户理解"为什么同一份数据会被读出不同故事"。

### 6.5 演化页（EvolutionPage）— 时间维度
- **定位**：恒星完整生命周期及其对行星环境的决定性影响。
- **交互**：可拖拽时间轴展示恒星演化（年轻→主序→红巨星→白矮星），颜色/尺寸过渡，宜居带随恒星光度变化而移动。
- **个性化**：采用金色主题（创作者个性化改动，视觉规范层面尊重保留）。

### 6.6 我的星表（MyStarsPage）— 收藏与回访闭环
- **定位**：个人收藏 + 数据更新回访机制（对应加分项）。
- **回访横幅**：后台比对 NASA/MAST 新数据，收藏行星有光谱更新时顶部横幅提示"你收藏的 K2-18b 有新的光谱数据发布了"，点击跳转最新对比视图，形成"探索→离开→更新→回访"循环。
- **状态管理**：Zustand + localStorage 持久化收藏。

理由：短期竞赛（≤2 周硬截止）中，部署在线服务的跨域调试与稳定性风险（CORS、服务可用性）远高于其开发便利价值；JSON 硬编码确保前端在任何情况下都能运行，即使后端完全失败项目仍可提交，风险为零。因此前端 30 颗行星数据硬编码于 `planets.ts`（字段已对齐后端协议，后端真实数据到达后可整体替换），光谱数据预解析为 JSON 缓存。

### 8.4 科学计算方法（保证科学准确性）
- **轨道半长轴**（开普勒第三定律）：`orbitAU(period, mass) = (P/365.25)^(2/3) × M^(1/3)`，M 为恒星质量（太阳质量）。
- **宜居带边界**（Kopparapu 2013 保守边界近似）：`habitableZone(luminosity) = { inner: 0.9√L, outer: 1.7√L }`（AU）。
- **判据阈值**：岩石性 ≤1.6 R⊕（岩石）/1.6–3.5（混合或海洋）/>3.5（气态）；温度窗口 223–323 K；M 矮星周期 <15 天判定潮汐锁定。
- **ESI 地球相似指数**：0–1，作为"像不像地球"的综合标尺。

## 9. 核心技术难点与攻坚（技术困难）

### 9.1 科学准确性：M 矮星轨道质量修正（最关键的科学 bug）
- **问题**：TRAPPIST-1e 被错误标记为"宜居带外"（暗红光斑），实际应在带内。
- **根因**：`orbitAU()` 默认假设恒星质量≈太阳（1 M☉），直接 `a=(P/年)^(2/3)`。但 TRAPPIST-1 仅 0.09 M☉，轨道半径被高估约 2.2 倍，宜居带判据完全失效。
- **修复**：为 23 个系统在 `starParams` 补全 `mass` 字段；`orbitAU()` 接收 mass 参数，应用完整开普勒第三定律 `a=(P/年)^(2/3)×M^(1/3)`；更新 SystemView3D/GalaxyPage 调用处。
- **验证**：TRAPPIST-1e 正确显示青绿（宜居带内），TRAPPIST-1d 否决理由正确归因于"无大气层"而非轨道。
- **教训**：科学计算必须考虑物理参数，不能假设所有恒星类太阳；G 型星可省略质量修正，M 矮星/白矮星必须计入。

### 9.2 视觉攻坚：从"扁平绿环带"到 shader 弥散能量场
- **问题**：初版宜居带是半透明绿色 annulus + 硬边界 + 文字标签，用户反馈"太丑，没有宇宙美感"；文字版判决清单"像表格"。
- **方案**：shader 程序化生成（避免主观审美反复试错）——HabitableZoneGlow 弥散星云环带 + AuraVerdict 气场光斑系统（用光晕颜色与动画节奏表达结论）。
- **成效**：3D 环带与右栏光斑共享"弥散、有机、能量场"视觉隐喻，强化探索主题；Puppeteer 验证 18/18 通过。

### 9.3 视觉迭代的回退决策与基线管理
- **情境**：星表视觉升级经多轮迭代（v4 简化版：删 SunGlow、降密度、双层光点），用户仍反馈"效果不如修改之前"，画面显杂乱。
- **决策**：识别出 v4 元素堆砌（星云、尘埃带、核球、衍射芒）导致主体不突出；果断 `git checkout` 回退到上一稳定版本（commit 25e965c，第一版 SpaceEngine 视觉升级版），保留实验性思路作技术债注释。
- **教训**：当用户对视觉连续负反馈且无明确方向时，回退到稳定基线优于继续主观微调；记录失败原因与已验证参数范围，避免重复试错。

### 9.4 渲染性能：分层渲染
5000+ 全量数据若全部做可交互 3D 会严重卡顿。方案：Canvas 批量撒点画不可点击背景星空 + 精确交互层只渲染约 30 颗重点行星与筛选命中目标，兼顾数据完整性与交互性能。

### 9.5 可视化库陷阱
- **Nivo Radar 数据方向误用**：nivo radar 的 `data` 语义是"每行一个维度指标（轴）"，`keys` 才是"数据系列（行星）"，与直觉相反。按常规传入（每行一个行星）导致所有点 x 坐标为 0，渲染成一条垂直线（path `M0,-93.98L0,29.21Z`）。修复：转置数据结构，`indexBy="指标"`，`keys={['K2-18b','地球']}`。
- **极坐标轨道半径退化为零**：N 层同心半圆用 `gap=R0/(N-1)` 时，最内圈 `r=R0-(N-1)×gap=0`，SVG 弧退化成点（`A0,0`）。修复：改用 `gap=R0/N`，最内圈 `r=R0/N>0`。

### 9.6 交互叙事：三拍时间轴的自动播放与接管
自动逐拍点亮（2.6s/拍）与用户点击的冲突处理：用户点击任意节点即清除自动播放 interval 并**永久接管**（同拍再点收起详情），章节重进时重置；3D 星球曝光/主色/大气色随拍 tone 每帧 lerp 联动。

### 9.7 工程与部署踩坑
- **中文计算机名崩溃**：机器名"袖立333"（含非 ASCII 字符）导致 EdgeOne/Vercel CLI 把 `os.hostname()` 当 HTTP 头发送时 ByteString 崩溃。解决：`hostname-patch.cjs` 通过 `NODE_OPTIONS=--require` 注入，覆写 hostname 为 ASCII。
- **EdgeOne 默认域名 Token 门禁**：所有默认域名（`.edgeone.cool`/`.edgeone.dev`）裸访问一律 401（`X-EOP-MSG: eo_time missing`），CLI 给的临时链接约 3 小时过期。唯一永久公开方案=绑自定义域名；海外区域免备案，含中国大陆区域需 ICP 备案（1–3 周）。
- **Vercel 深链 404**：SPA 路由直接访问子路径 404，用 `vercel.json` rewrite 全量指向 index.html 修复。
- **PowerShell 执行策略**：用 `.cmd`（edgeone.cmd/npm.cmd）绕开 .ps1 拦截；`&&` 不支持改用 `;`。
